## 关键回合配图：可行，建议先做玩家主动触发

以下是后续功能方案，尚未实现或启用自动生成。

第一版在开场、首次进入重要地点、觉醒完成、重要物品获得或章节收束等**已经保存的关键回合**，提供“生成场景图”按钮。资格应来自故事配置与已确认的回合事件，不把普通对话或每次状态变化都视为关键时刻。按钮旁独立显示图片费用及上限，玩家点击后进入异步队列，继续阅读和游玩。后续再提供有每日额度、冷却和总预算的自动配图选项。

插画绑定当前回合和当前分支，出现在该回合正文之后、行动选项之前。使用固定 3:2 画幅占位，显示排队、生成、完成与失败状态；到图时保留阅读位置。旧回合直接读取已保存的图片，不重复生成。切换回合、刷新或网络恢复均不能把图片挂到其他分支。失败提供明确原因和重试入口，正文与存档始终可用。

## 可以复用的工程基础

- `rpg/agents/image_gen/openai_compat.py` 已支持兼容 Images API。
- `rpg/platform_app/image_jobs.py` 已有异步入队、状态、图片存储与完成通知。
- `rpg/platform_app/postproc_queue.py` 和现有 worker 可以复用队列基础；应为图像任务配置独立并发与超时，避免占用文本后处理容量。
- 玩家端已经有回合、分支、保存结果、报价及余额状态，可作为展示和交易的集成点。

现有通用图像任务按用户凭据解析模型，玩家服务则使用平台管理的模型配置。通用生图接口不能直接作为玩家配图入口。玩家 Reader 目前也没有图像任务的读取和展示协议，文本积分报价不能当作图片报价使用。

## 上线前必须补齐的闭环

1. **平台图片服务配置**：由后台管理模型、服务凭据、画幅和输出预算；Key 加密保存在服务端，不进入玩家 DTO。凭据所有者与任务归属玩家分别保存。
2. **场景与知情边界**：服务端根据对应 commit 的已公开正文和状态构造最小场景描述，只提供玩家已知的地点、人物外观、动作与物品。后台秘密、未来章节及其他存档数据不进入提示词。第一版优先场景与人物背影，之后再建立经确认的角色外观参考，避免人物每次变脸。
3. **独立图片报价**：模型图片价格、平台积分价格、版本和费用上限明确配置。复用钱包预留、成功结算、失败释放的事务规则，图片成功落盘后才向玩家结算；不把它伪装成文本 Token 费用。
4. **幂等与并发**：使用 `(user_id, save_id, commit_id, style_version)` 去重。任务领取、钱包预留和最终发布均有状态锁；重复点击、轮询、worker 重启不能重复结算。不确定的供应商响应不能盲目再次调用并再次向玩家收费。
5. **权限与持久化**：业务记录同时绑定存档、分支和 commit；创建、查询、图片读取都校验当前玩家及可读历史。封面是公开素材，私人剧情插画使用受保护的存储接口。删除、导出和存档恢复需携带相应关联。
6. **资源上限与失败恢复**：每人每天、每存档每关键节点设限；配额查询异常时拒绝新增收费任务。设置排队过期、生成超时、供应商限流与失败退回状态。文字生成不等待插画完成。

验收覆盖双击/刷新幂等、多个浏览器并发、余额不足、报价过期、worker 崩溃、接口超时、生成失败、跨用户读取、切换分支、删除存档、历史阅读不跳转和移动端图片到达后的滚动稳定性。
