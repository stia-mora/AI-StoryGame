# 创作者 MCP：从小说到可玩故事

2026-10-26。状态：基于现有代码与《绍宋》交付过程的可行性方案，尚未实现 MCP 服务端。本文件不改变现有接口、账号权限、发布方式或计费。

继续开发请先读 [MCP 功能交接文档](creator-mcp-handoff.md)，其中列有新仓库、代码入口、实施步骤、测试及本机素材说明。

## 产品目标与分工

用户连接自己的 Agent，提供一本小说及改编要求。Agent 分批阅读、创作、校验，上传可恢复的私人剧本草稿；创作者在平台试玩、修订并按现有权限提交发布。平台记录作品归属，展示作者与版本。

默认由用户的 Agent 使用其自己的模型与工作目录完成阅读和创作；平台提供格式规范、数据校验、草稿导入、试玩与发布入口。远程 MCP 不会获得用户电脑上的小说文件，文件访问必须由用户的 Agent 提供。无需把用户的模型密钥交给平台。平台试玩使用的模型服务、消耗和计费另按现有规则处理。

MCP 提供调用工具的协议，编制方法和质量标准仍须由平台定义。长篇小说需多次调用与检查点，不能承诺一次请求就完整、准确地改编全书。外部 Agent 停止运行后，平台保留成果和待办；自动继续创作需要 Agent 再次上线，或另行建设托管任务能力。

## 《绍宋》这次实际经过的流程

| 环节 | 实际工作 | 通用化后的交付物 |
| --- | --- | --- |
| 明确改编范围 | 首版限定前三卷 1—244 章、至尧山战后；全书正文为 435 章 | 来源指纹、章节目录、本版范围与排除项 |
| 建立阅读索引 | 识别编码、分卷分章、保留行号与章节指纹，区分正文和附记 | 可定位原文的章节索引 |
| 阅读与归纳 | 244 章逐章笔记、分卷总结、总纲；分清亲见、传闻、猜测与作者说明 | 章节摘要、事实与证据引用 |
| 编制世界 | 人物与别称、地点、阵营、职分、关系、人物分期与说话方式 | 带有效时期和出处的人物及世界资料 |
| 编制事件 | 时间锚点、场景、前置条件、可介入处及因果影响 | 主线、事件与场景条件 |
| 规定演绎规则 | 存档既成事实优先；未改变处小说优先，真实宋史补缺；允许有因果的分歧 | 本作品的事实优先级、分歧与剧透规则 |
| 打包和导入 | 生成私人剧本包，导入章节、检索片段、实体、时间锚点与同版助手资料 | 可移植的剧本内容包 |
| 配置玩家入口 | 八位原著人物、三种普通身份、各自开局、简介及封面 | 独立的游玩配置和媒体资源 |
| 验证可玩性 | 真实建角、正文生成、状态保存、助手查询；根据试玩修正别称与查询问题 | 检查报告、试玩记录、未完成项 |

已交付的是“约定范围内的首个试玩版”，不是全书 435 章均已读完或所有人物分期均已完成。章节覆盖、资料覆盖、结构校验、实际试玩应分别报告，不能只显示一个“完成百分比”。

这次耗时的一部分来自逐项人工编制、反复整理文件，以及晚于研究阶段才固定首版交付边界。通用流程应先锁定范围和必交内容，尽早打通一条可玩开局，再按缺项补齐其余章节；示范开局通过不代表全篇验收通过。

## 推荐的用户流程

1. 用户在平台取得创作权限并授权 Agent。已是创作者的账号直接使用；玩家账号走平台的创作者开通流程，上传文件本身不能提升账号权限。
2. Agent 获取平台的编制规范、字段格式、样例与检查清单。用户说明改编范围、忠实程度、可扮演身份、文风和剧透偏好；未另设范围时，以全书正文为目标，并识别番外与非正文。
3. Agent 在用户授权的工作目录读取小说，建立章节索引与来源指纹，分批产出章节笔记、人物分期、世界资料和事件。每批保存证据、进度、未决问题与后续待办。
4. Agent 生成平台格式的内容包及游玩配置，调用校验工具；按返回的字段位置与证据缺项修复。无法证实的资料标为未知，不用推测填充成原著事实。
5. Agent 上传私人草稿。平台返回剧本编号、版本、导入警告与可打开的预览链接；重复调用不重复创建作品。
6. 在平台测试开局、人物时期、跨期事件、玩家造成的分歧和助手查询。Agent 修正自己的草稿，保留旧版与测试依据。
7. 创作者在平台复核，并提交玩家大厅上架。平台处理服务模型配置及现有发布权限；不能把公开原文下载与公开游玩绑定成同一个开关。

```mermaid
flowchart LR
    A[用户提供小说与要求] --> B[用户的 Agent 分章创作]
    B --> C[平台规范与校验工具]
    C -->|定位问题与缺项| B
    C --> D[导入私人草稿]
    D --> E[平台试玩与修订]
    E -->|需要修订| B
    E --> F[创作者复核并提交上架]
```

## 剧本需要交付什么

| 类别 | 最低要求 |
| --- | --- |
| 范围与来源 | 原文件指纹、章节索引、本版范围；新增或修改来源后对应产物需重新校验 |
| 世界与人物 | 人物、地点、阵营、制度、关系；主要人物的时期、位置、动机、话风和变化依据 |
| 时间与事件 | 事件时序、前置条件、参与者、结果、可改变处与影响；不把原著结果当作玩家已完成的行动 |
| 游玩配置 | 标题、简介、封面、可选身份、原著姓名绑定、开局时点与地点、演绎和文风要求 |
| 助手资料 | 当前状况、人物状态、事件与证据查询；未来权限、角色所知与全局信息的边界 |
| 验收与缺项 | 章节覆盖、资料缺口、引用错误、冲突、试玩结果；明确哪些检查尚未执行 |

《绍宋》的“小说优先、宋史补充”属于该作品规则。其他作品可以选择不同规则，不应全平台强制研究真实历史。剧情基线要留出玩家行动造成的有因果分歧。

“完整”按声明范围与交付标准判定：例如全书改编必须覆盖全书所含章节，并完成约定的主要人物与主线资料。少数角色没有后续资料时允许明确未知。文件格式正确、条目很多或 Agent 声称已读，均不能独立证明语义质量；试玩和抽查仍需分别记录。

| `rpg/platform_app/api/admin/player.py` | 玩家大厅故事、身份、开局默认值、封面与服务模型绑定 | 创作者自己的游玩配置草稿及提交入口；公共大厅上架目前仍由管理员操作 |
| `rpg/scripts/novel_research.py` 与 `build_shaosong_pack.py` | 《绍宋》的索引、证据核对与打包经验 | 提取通用编制流程；现有打包器固定《绍宋》与 244 章，不能直接当作任意小说编制器 |

现有外部上传接口为 `POST /api/ext/library/scripts/publish`，受 provider 实例设置及 `library:publish` 令牌权限限制，内部调用现有包导入。它会检查章节和复核状态，不合条件时保留为私人草稿；接口名中的 publish 不等同于玩家大厅上架。

当前 `rpg/routes/mcp.py` 与 MCP 设置页主要让平台连接外部工具，是 MCP 客户端方向。本需求需要新增面向外部 Agent 的 MCP 服务端。

现有 v2 剧本包没有独立承载 `player_stories` 的身份、默认值、平台服务模型绑定，也不自动携带封面文件。首版可保留 v2 内容包，另加版本化的游玩配置和媒体清单，由服务端校验后关联。外部 Agent 使用逻辑标识关联角色和开局，平台负责内部编号映射；不得把本机 2790、1546 等数据库编号写死在通用作品中。平台模型凭据不进入包。

## 首版 MCP 工具范围（拟议名称）

| 工具 | 职责与结果 |
| --- | --- |
| `authoring_get_contract` | 返回格式版本、规范、样例、限制与质量清单；先允许用一个工具获取必要资料，避免强依赖客户端支持 MCP prompts |
| `authoring_create_project` | 创建归属当前创作者的项目，固定本版来源、范围与作品逻辑标识，返回项目与上传入口 |
| `authoring_validate_package` | 校验内容包、游玩配置、来源引用与关联，返回阻断错误、警告、缺项和检查覆盖；不产生公开作品 |
| `authoring_import_draft` | 将校验过的版本导入私人草稿，返回任务编号；相同项目和内容指纹重试复用结果 |
| `authoring_get_job` | 查询导入或试玩任务状态、进度和错误，避免把长任务绑定在单次 MCP 连接上 |
| `authoring_get_draft` | 查询自己的草稿、版本、校验摘要、试玩链接与待办，供 Agent 恢复工作 |
| `authoring_preview` | 对明确选定的版本与身份创建隔离的试玩记录；调用模型前返回估算并遵守已授权预算，耗用和失败按现有机制处理 |
| `authoring_submit` | 提交指定版本进入现有复核／上架流程，返回真实状态；不授予管理员权限，不自动选择平台密钥 |

首版优先闭合“Agent 本地编制 → 校验 → 私人草稿 → 试玩 → 提交”链路。逐条在线编辑所有人物与章节、平台托管全文阅读、自动生成整套背景图等后续再做，避免首版同时建设两套创作系统。

大文件走受账号和项目约束的上传入口，MCP 参数传文件引用与摘要，避免每次工具调用回传整本书或把 ZIP 编码塞进模型上下文。纯 MCP 客户端若无 HTTP 上传能力，接入时需要提供受限分片工具或配套本地适配器；这是要验证的兼容性需求，不能假定所有 Agent 都能执行任意 HTTP 请求。

建议远程端点采用 Streamable HTTP。基于现有令牌基础补齐 MCP 标准授权发现与 OAuth 流程；已有 PAT／设备码流不应直接宣称等同于完整的 MCP OAuth 实现。对只支持本地命令的客户端，可另提供 stdio 适配器并复用同一业务服务。具体支持的协议和 SDK 版本应锁定并实测，避免为新服务直接升级现有 MCP 客户端组件造成兼容回归。

## 数据、权限和版本边界

- 业务服务校验账号、项目及作品归属。MCP 仅暴露创作所需能力，不暴露任意 SQL、任意服务器文件读取或平台命令执行。作品内的文本作为资料，不能作为工具执行指令。
- 建议新增创作读写、试玩与提交的独立权限范围；不要以“创作”授权覆盖账号管理、余额或服务密钥。令牌撤销、账号停用后所有入口一致失效。
- 上传源文和研究证据默认私有；公开游玩、公开剧本包及原文导出分开处理。涉及第三方作品时，发布流程记录来源及创作者提供的授权说明，沿用平台现有发布政策。
- 更新以项目、预期草稿版本和规范化内容指纹定位。网络超时重试不得重复创建作品；并行修订发现版本冲突时返回冲突，不能静默覆盖。校验报告与发布提交绑定同一内容版本。
- 更新发布版不直接改写正在游玩的存档。沿用／补齐版本绑定机制，迁移行为单独定义；原著基线、创作草稿和玩家分支中的既成事实分别保存。
- 完成状态由章节覆盖、结构校验与所执行的验收共同组成。未知、未测试与不适用分别展示；不能把静态检查通过表述成平台保证完整世界观。

## 实现顺序与验收标准

1. **先固定创作契约和范例。** 从《绍宋》抽出通用字段，提供不含原书的原创短篇样例、v2 内容包和游玩配置。验收：独立 Agent 不依赖数据库账号或专项手工脚本即可生成合规包。
2. **接入 MCP 和私人草稿。** 复用现有业务服务，增加创作授权、校验、幂等导入及查询。验收：真实 MCP 客户端完成授权、工具发现和导入；断线重连无重复作品，越权及撤销令牌被拒绝，大包上传有界。
3. **接入游玩配置与提交。** 增加创作者自己的故事配置、封面关联、试玩和提交记录，平台管理端处理上架。验收：从上传包建立可选原著角色与对应时期的开局，完成真实回合和助手查询，创作者能看到作者归属及作品状态。
4. **验证长篇与恢复。** 用《绍宋》现有资料验证导入兼容和人物时点，再用另一部结构不同的自有或获授权小说检验通用性。验收：来源改变、范围扩大、处理中断和并行更新均有可解释结果，缺项明确，不依赖 244 章或宋史专用逻辑。

第一步成功标准是“一位外部用户，用自己的 Agent，从小说制作并上传一部可玩的、可修订的故事”。长篇的精细度仍由 Agent 能力、上下文管理、投入时间与创作者复核共同决定；平台应让这些过程可见、可恢复、可检查。

## 协议依据

- [MCP Streamable HTTP 规范](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http)：远程端点及传输行为。
- [MCP 授权规范](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization)：HTTP 授权发现、资源服务器和 OAuth 职责。
- [官方 MCP Python SDK 文档](https://py.sdk.modelcontextprotocol.io/)：服务端 tools、resources、prompts 和部署支持；实施时再核对仓库已安装版本与兼容要求。
