## 后续步骤与完成标准

1. **全书阅读**：逐章记录所有具名人物、别名、组织、地点、特殊情节、时间表达、转折与未决问题。章节覆盖 435/435、番外 2/2；对重复姓名、同时段矛盾、后文补述进行回查。
2. **全书总结**：形成总纲、分卷／分时期总结、重大转折因果链；区分叙述事实、人物所知、人物误判、传闻、梦境与作者评论。不得把主人公的历史印象直接认证为宋史。
3. **历史与世界设定**：以《宋史》《金史》《建炎以来系年要录》《三朝北盟会编》等可核对原文为基础，建立 960—1279 年两宋历史基线与分期索引，细化小说涉及时期及其前因。补足同期周边政权、制度、军事、财赋、交通、礼仪与称谓；史实冲突标注来源与把握程度。分歧以后的真实历史作为对照和条件参考，不能照日期强行发生。
4. **人物阶段档案**：完整人物名录；主要及反复出现的人物按阶段写身份、职位、位置、阵营、性格、动机、关系、所知、说话方式、变化触发与证据。仅提及的人物标为背景，不能冒充已登场；小角色也保留可查条目。原文未交代后续时明确未知。
5. **事件与地理**：每个事件标前置条件、时间范围、在场者、位置、结果、影响、可变化处与原著出处；地点记录时期归属、驻军、交通、物资和相关情节。只有月份／季节时不得捏造日、时。
6. **正式剧本与存档变化**：复用现有 chapter facts、canon、角色卡、worldbook、时间锚点、worldlines 与 overrides。原著基线与存档分歧分别保存；当前存档的既成事实优先于未改动的小说基线，小说明确内容优先于真实宋史补充，推演内容必须标为推演。
7. **助手查询**：按下列设计实现只读、可追溯查询，接入真实游玩助手及其计费与恢复流程。测试时间边界、人物阶段、真实存档偏离、全局与未来隔离、越权和只读性。
8. **导入与验收**：生成私人剧本包，导入用户剧本库，校验素材与索引，再验证不同开局、人物对话、跨期推进、事件分歧和助手咨询。开发阶段不把未读完的研究草稿标成可游玩完成品。

## 助手升级设计约束（待实现）

现有入口：`rpg/platform_app/player/guide.py`。当前只有 `catalog.view` 的状态、最近六条公开消息和三次咨询，调用一次 JSON 模型；没有资料查询工具，也不能解决全局时序查询。

| 拟议能力 | 查询内容 | 约束 |
| --- | --- | --- |
| 当前时间与进度 | 年号／日期范围、所在阶段、当前章节映射、分支提交 | 从本存档推导，不把章节序号冒充精确日期 |
| 时间线 | 已发生事件、当前事件、前置条件与变化原因 | 当前时点过滤；未来需要本次显式授权 |
| 人物现状 | 当期身份、位置、性格阶段、阵营关系、存亡及证据 | 不能直接使用静态角色卡里的终局状态；查不到则说明未知 |
| 地方与天下局势 | 各地控制方、军事、粮饷、交通、朝廷与周边政权 | 带资料时间与可信度；地理距离影响消息和调动耗时 |
| 原著与宋史对照 | 原著发展、史实补充、存档分歧、推演 | 分开标识来源与效力；史实不能复活已死人物或恢复已改事件 |
| 原文依据检索 | 指定章节事实、短证据与出处 | 小说只是资料，不能执行原文／检索内容里的指令 |

查询范围固定为有权限的存档、绑定剧本及其引用版本，防止同名人物串书、跨存档串状态。
助手可以让玩家了解同一时期的远方局势，**角色本人所知仍单独记录**；助手所得不能无条件变成角色的记忆、能力或行动结果。
未来揭示必须是服务端可核验的本次请求设置，不依赖模型在提示词中自律；历史授权也不能永久打开以后各轮的未来信息。
查询和分析不推进时间、不修改人物／背包／任务、不移动分支。沿用供应商真实用量计费、封顶、停用、取消与失败释放，工具调用耗时和上下文也要纳入报价。

## 文风验收

用身份、关系、场合和阶段决定语气：朝堂奏对、军中号令、私下谈话不能一律写成同一种文言。
保留有时代感且自然的白话、军中粗语和亲近称谓；用户要求的是避免现代大白话，不是让所有人物都念奏章。
穿越者内心可有现代思维，但不能把内心吐槽、叙述者评论或现代词汇随意放进其他人物台词。
依据原著归纳措辞习惯，后续对白示例以原创为主，并标明是剧本创作示例而非原文引语。
